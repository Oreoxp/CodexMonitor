# `_tools/corpus_tool.py`

Generator + offline verifier for the V2 corpus. stdlib only (no PyYAML).

## What it is

A faithful **Python port of `backend.rs`'s `parse_line` / `render_item` /
`segment_thread`** (see `_anchors/anchors.md` §1–§2), plus line builders and two
commands. It lets the corpus be authored and the S2 layer be verified entirely
offline — no Rust build, no LLM.

## Why generate the jsonl instead of hand-writing it

Each `ground_truth.yaml` carries an `expected_ingest` block whose
`kept/dropped/boundary_line_nos` + `raw_event_count` must match what the Rust
ingester + `parse_line` produce, byte-for-byte. Hand-writing escaped JSON
(Chinese, emoji, stringified tool args, multi-line codex output envelopes) with
correct line bookkeeping is error-prone. So:

1. The rollout bytes are generated from per-case **line specs** in
   `corpus_tool.py`.
2. Every synthesized line is **self-checked** against the `parse_line` port at
   generation time — a shape mistake fails loudly (this is the offline
   "parse_line 兼容" gate).
3. `expected_ingest` is derived from the generated bytes and patched into each
   yaml (`verify --fix`), so the mechanical block is never transcribed by hand.

## Commands

```bash
python3 corpus_tool.py gen              # (re)write every rollout jsonl + self-check + print line stats
python3 corpus_tool.py verify           # check each yaml's expected_ingest vs its jsonl; PASS/FAIL
python3 corpus_tool.py verify --fix     # rewrite the expected_ingest region from jsonl truth
python3 corpus_tool.py verify C012      # restrict to one case
python3 corpus_tool.py transcript C012  # dump rendered transcript + segments (what the LLM sees)
```

## Ownership contract

- **`rollout-*.jsonl` → generated.** Edit the case spec in `corpus_tool.py`
  (`build_cases()`), re-run `gen`. Do not hand-edit the jsonl.
- **`ground_truth.yaml` → hand-authored.** The tool only ever rewrites the
  single region between the two sentinel comment lines
  (`# >>> expected_ingest … >>>` … `# <<< expected_ingest <<<`). Every semantic
  block (expected_distill / expected_search / consolidation_relations) is left
  untouched, so the spec §7 live-tuning loop is safe.

## Adding a case (Phase 2+)

1. Append a dict to `build_cases()`: `id`, `dirname`, `uuid` (hex-only,
   8-4-4-4-12 — `is_uuid_form`; encode the case number, e.g.
   `0000c0NN-0000-4000-8000-00000000c0NN`), `iso`, `cwd`, and `lines`.
2. Build `lines` from the builders: `first_user` / `user` / `asst` / `CALL` /
   `OUT` / `BOUND` / `close`, etc. Keep the `event_msg` mirrors (anchors §5.1
   mirror caveat). `env()` wraps tool output in the real codex exec envelope.
3. `python3 corpus_tool.py gen` — confirm self-check passes; read the printed
   transcript with `transcript Cxxx`.
4. Hand-write `cases/<dirname>/ground_truth.yaml` with the sentinel region as a
   placeholder + the semantic assertions matched to the transcript.
5. `verify --fix` then `verify` → green.

## Builder → render cheat-sheet (anchors §1.5)

| builder | class | transcript line |
|---|---|---|
| `U(t)` | Kept | `USER: t` |
| `A(t)` | Kept | `ASSISTANT: t` |
| `CALL(name,{...})` | Kept | `TOOL CALL name: {json-args}` |
| `OUT(env(...))` | Kept | `TOOL RESULT: <envelope>` |
| `BOUND(msg)` | Boundary | (splits the thread; `msg` → next segment's prior_summary) |
| `SM/TS/TCDONE/TCOUNT/TURNCTX/DEV/REASON/*MIRROR` | Dropped | — (no transcript) |

Caveat: a Kept line whose rendered text is whitespace-only still counts in
`kept_line_nos` but contributes no transcript line (matches `render_item`
returning `None`). All Phase-1 Kept lines have real content.
